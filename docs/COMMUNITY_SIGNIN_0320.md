# 0.32.0 多账号社区签到

## 已实现

1. 总览新增社区签到功能卡：今日完成数、待处理提示、已签到账号及官方区服累计天数，可进入签到管理。
2. 社区签到页面改为今日概览、自动签到开关、账号列表和账号设置。复用软件银白/深色主题，不新增独立配色体系。
3. 最多保存 30 个本机账号档案，分别命名、登录、选择区服、选择是否参与自动签到。账号名称是用户备注，不冒充官方返回的身份。
4. 勾选多个账号后，一键顺序签到；结果分别显示，单个登录失效或网络错误不阻断其他账号。已确认今日成功的账号跳过。
5. “打开软件自动签到”默认关闭，需要在功能内确认开启。下次启动执行所选账号，不创建 Windows 自启项、计划任务或常驻后台。关闭应用时终止后续队列和在途请求。
6. 旧版单账号 partition、加密 Cookie 和区服选择保持原路径，首次载入为“默认账号”。新账号使用不同的 persistent partition 与加密快照目录，凭据不传给渲染页面。

## 状态与限制

- 今日按北京时间日期记录。只有官方签到成功，或明确返回“今日已经签到”，才记录今日成功回执；不能仅凭累计天数判定今日已签到。
- “待签到”表示本机尚未确认今日成功，不能断言用户在微信等其他渠道没有签到；页面已说明。
- 累计天数来自活动 `init` 的 `days_num`，不是推测值，也不是连续签到天数。刷新失败保留原查询时间，不虚构加一天。
- 自动请求前写入尝试记录，结果未知时当天重启不自动重试；用户可刷新核对后手动发起。
- 同一官方账号重复保存在不同档案中，不能仅凭备注去重。每个档案应登录不同账号；官方仍决定重复签到是否被接受。
- 蜗牛盾、密保卡、验证码和账号密码在官方窗口由用户输入。登录过期需要重新验证，不保证永久免登录，不规避活动服务端限制。
- 修改右侧区服但未保存时，单账号签到按钮禁用；批量使用账号列表中已保存的区服。

## 验证

- 57 项 Node 回归测试通过，包含新增多账号隔离、旧版兼容、跨重启回执、北京时间跨日、默认关闭、自动签到防重复、批量失败隔离、并发锁、账号移除和损坏索引保护。
- TypeScript 和生产构建通过；原有 JavaScript 主包体积提示仍存在，不影响构建。
- 真实 Electron 隔离 profile 检查通过：两账号独立区服选择，27 个分区、207 个服务器，Windows 加解密正常。未登录真实用户，真实签到请求为 0。
- 通过浏览器操作真实 React 组件的隔离示例：添加账号、切换账号、分区联动、同 ID 不同服务器名称保存、未保存区服锁定、批量进度、部分账号需要登录、自动开关确认与移除确认。
- 银白和深色截图检查完成；980px 窗口切换单列，无水平溢出，示例页无控制台错误。示例数据仅存在 tests 中，不进入生产包。

真实账号完成签到、官方二次验证分支和服务端会话长期有效性仍需用户登录验证。测试不会把模拟成功当成真实账号签到成功。

## 使用

退出旧版并打开 0.32.0 → 社区签到 → 使用默认账号或添加备注 → 官方登录 → 关闭登录窗口并刷新 → 保存区服 → 勾选账号 → 一键签到所选。

自动签到需另外开启，并为相应账号勾选“参与自动签到”，从下次启动生效。
