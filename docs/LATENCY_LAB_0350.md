# 0.35.0 延迟测试、实验室提醒与侧栏快捷入口

## 使用入口

- 实验室 → 系统延迟测试：15 / 30 / 60 秒测试，名称备注、平均值、P95、P99、峰值、采样曲线、本地历史与基线差值。
- 进入实验室默认显示须知，可勾选“以后进入不再提示”。在“实验须知与提醒设置”取消勾选并保存，可重新启用。偏好存入本机应用状态目录，不依赖临时服务端口；关闭此提醒不会关闭具体操作确认。
- 系统调整、网络优化、实验室、实时监控、更多工具支持悬停展开快捷面板。点击右侧箭头也可展开，支持方向键、Tab 和 Escape。系统、网络、实验室可直接定位子页。原菜单点击行为、手机窄屏菜单和左下角签到入口保留。

## 测试口径

测量方法为 `wake-overshoot-qpc-v1`：Windows 原生等待计时器请求 1 ms 相对等待，用 QPC 记录从设置等待前到等待返回的时间，再减去 1 ms。包含设置调用、计时器触发、唤醒及调度影响；负偏差钳制为 0。它不是从内核 ReadyThread 到 CSwitch 的纯调度延迟，不是输入到显示的端到端延迟，也不是网络 Ping。

普通优先级测试线程先预热 300 ms，再开始计数；不绑核，不修改游戏进程，不调用 timeBeginPeriod 或 NtSetTimerResolution。优先创建高精度计时器；只有明确的不支持错误才回退到普通计时器。模式显示在结果中，不同模式不计算基线差值。

P95 / P99 使用 nearest-rank 定义，曲线记录每约 250 ms 一组样本的最大值。完整统计使用所有已采集样本，最多 65000 个。停止的部分记录明确标为“已停止”，不与完整记录进行差值比较；保留本地 JSON，页面显示最近 50 条。

同一次基线比较要求两个不同的完整记录，测量方法、计时器模式、时长、系统版本信息和逻辑处理器数量相同。显示电源方案是否不同。后台负载仍由用户保持一致，差值不证明优化因果关系；不提供跨型号“合格分数”。功能方向参考 BoosterX，未确认其完整算法，不承诺数值可以直接横向比较。

采样按需启用，页面切换继续运行，关闭软件时停止并保存部分记录。与本服务的鼠标/DPC 测量互斥；不同服务实例通过命名互斥锁拒绝重叠测试。进程被强制终止时 Windows 释放计时器句柄，不留下系统设置；未完成的内存样本不会在崩溃后恢复。

报告中的 CPU 数字为本地服务整个进程在采样区间内的 CPU 时间除以墙钟时间（单逻辑核心 100%），包含同进程其他任务，不伪称纯采样线程开销。

## 验证记录

- 102 项 Node 回归通过；TypeScript、Vite 和 Windows x64 便携版打包通过。现有单 JS chunk 大于 500 KB 的体积提示仍存在。
- `Test-LatencyLab.ps1`：真实高精度原生计时器连续测试 15 秒，10520 个样本；nearest-rank 统计、重复启动拒绝、取消响应、完整/部分历史保存、提醒持久化与恢复通过。未修改系统设置。
- `Test-SessionLabHost.ps1`：HTTP 启动、提醒读写、诊断互斥、关闭时取消并保存延迟记录通过；同时回归旧会话应用回读与关闭前恢复。
- 真实本地服务页面端到端验证：点击“开始测试”显示口径确认，确认后采集 15 秒得到 10394 个样本，平均 0.442 ms / P95 0.518 ms / P99 0.529 ms / 最大 5.569 ms。该结果只证明链路工作，不是电脑优劣或优化效果结论。
- 在真实服务中验证“不再提示”：重载后不再出现；取消勾选并保存、离开后再次进入则重新弹窗。侧栏验证悬停、点击、方向键、Escape 和系统子页跳转，深浅主题可读。
- UI 按 emil-design-eng 的交互细节原则实现：200 ms 防误触展开、180 ms 离开缓冲、固定浮层不挤动内容、键盘无等待过渡、原生 dialog 焦点约束。
- 测试服务使用独立临时状态目录，未修改用户原有提醒偏好、签到账号、游戏、电源及显卡设置。未启动便携版替换用户当前实例。
