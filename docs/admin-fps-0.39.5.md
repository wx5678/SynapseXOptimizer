# 0.39.5：账号角色、帧率范围与到期恢复

## 已确认规则

- 普通及 VIP 用户可输入 60–300 FPS；原版 TrackBar.Minimum=20，对应最低 60 FPS。按 3 FPS 步进向下换算，不承诺任意整数恰好生效。
- 高于 300 的修改仅软件管理员可执行，最高输入 1000，实际最高 999。VIP 不再授予 `jiuyin.fps`；旧的单项 feature 字符串也不能代替管理员角色。
- 网页后台操作员与软件管理员分离。软件账号默认 user，仅后台已登录操作员可 promote/demote，有 CSRF、原因与幂等审计；没有自动提权任何现有用户。
- 软件管理员不限登录设备；没有旧十会话上限。每台设备独立会话、独立签名凭证。原有 VIP 权益不自动改变。
- 管理员自身保留高上限；普通用户 VIP 有效时保留已有高上限，成功联网同步确认 VIP expired 后恢复原版 300 资源。
- 断网、退出账号、未购买过 VIP、授权状态不明、撤销而非到期都不被猜测为会员到期。
- 应用修改或导入验证过的原版备份后纳入恢复管理；不扫描全盘，不接管未知第三方修改。

## 实现边界

- 主进程开始高上限操作和实际写入前都同步服务端身份；短期 Ed25519 `account_role=admin` 凭证绑定 user_id/device_hash。显示用的 `user.role` 与普通授权字符串不能作为可信角色。
- 管理员凭证最长五分钟；高上限写入仍必须在线。取消角色注销所有账号会话、清空旧绑定，重新登录后恢复单设备限制。
- 自动恢复每分钟检查，当前软件必须运行。游戏运行时提示等待退出，不杀游戏、不强行替换使用中的资源。退出软件会等待正在进行的恢复检查/操作结束。
- 恢复只恢复 `skin.package` 原版资源上限，不直接改写每个游戏账号已保存的 FPS 设置，不保证正在运行的游戏瞬间回到 300 FPS。
- 下调时只修改目标 Maximum 及其后的等量空白，保持解压长度和压缩块长度、其他资源字节不变。
- 法律风险并未因角色限制消失；此次是技术与权限实现，不是法律合规结论。
- 旧版安装包没有这些新规则。本次未设置强制更新、未上传 Gitee，也不保证对修改过客户端的人强制执行授权规则。
