# 0.39.3 工作台修复

## 问题与修改

- 自动候选未排除 System，且高 GPU 使用率可以让无窗口进程成为游戏候选。新增系统/远程控制进程排除，PID 0/4 不进入候选。已识别且仍存活的游戏保持绑定；九阴即使最小化或 GPU 暂时为零也保留。
- 候选原来使用 OrderedDictionary，Sort-Object 按属性名未正确排序；改为 PSCustomObject，明确按分数排序。显式 PID 消失时返回无目标，不替换成同名其他实例。
- 首页依赖自动报告发布采样；多个采样来源和目标变化可能重置趋势。改为首页独立只读轮询现有采集器（FPS 1 秒，遥测最多每 3 秒），与自动报告开关解耦。慢遥测不阻塞 FPS 读取；页面卸载、绑定变化后的迟到响应不发布。
- 后台报告不再向首页数据仓库写入，也不因与运行中采集器目标不同而抢夺采集器。补充异步响应卸载检查。
- 采样仓库拒绝系统进程，短时间空结果不覆盖有效帧数据。帧时间缺失时用有效 FPS 的倒数换算平均帧时间；不伪造 FPS 或 1% Low。
- 图表对高帧率使用更细的纵轴刻度；单点显示等待积累提示，不再错误地让用户重新开启已运行的采集。
- 桌面侧栏右移 8 px（left 12 → 20），内容同步让位。左下签到按钮调整为 44×44，居中于图标栏，并与下方备份分隔线留出间距；保留单个签到入口。

## 验证

- 全部 Node 回归 145/145 通过。
- Windows PowerShell 5 与 PowerShell 7 隔离测试通过：System 高 GPU 排除、焦点改变保持目标、最小化九阴保留、指定 PID 不替代、进程退出重新选择。
- 本机真实进程只读检测：fxgame.exe / PID 52960，13 个候选，System 候选 0。未调整进程或系统配置。
- 浏览器使用实际 App 组件与隔离模拟 API，关闭自动报告后持续展示约 600 FPS 和一分钟平均帧时间曲线。1360×860 检查侧栏 left=20，签到按钮 44×44，底边756，备份按钮上边765.35，无重叠。
- 前端构建及 Windows 便携版打包完成，打包后的 RealtimeMonitor 模块哈希与源文件一致。
- 没有关闭正在运行的用户客户端/游戏；未用新安装包接管实际采集，也没有部署云端更新。需退出旧软件并打开新版进行实机使用确认。
